# midi2key (C# / .NET 9 Edition)
このアプリは、MIDIキーボードやMIDIシーケンサーのノート入力を、PCの生キーボード入力として変換する軽量なWinFormsアプリケーションです。

---

## 🎹 主な機能

* **超低遅延マッピング**: MIDIノートを任意のキー入力にマッピング
* **88鍵盤・音名表示対応**: 88鍵盤電子ピアノ（A0〜C8）に対応し、マッピング一覧に「C4 / ド」などの音階名を直感的に表示
* **サステインペダル（ダンパーペダル CC 64）対応**: 足元のペダル操作（SpaceやShiftなどの割り当て）を状態遷移マシンにより安定してサポート
* **DirectInput/ハードウェアレベル対応**: 内部で Windows API (`SendInput` + Hardware Scan Code) を叩いているため、通常のテキスト入力はもちろん、大半のPCゲーム（原神、Sky星を紡ぐ子どもたち など）でも物理キーボード入力として正しく認識されます！
* **和音・連打最適化**: Shiftも含めた一元化された参照カウント制御により、和音や素早い打鍵でもキーが途中で誤って離されないスムーズな演奏設計
* **NoteOn時スナップショット保持**: 演奏中にマッピングやJIS/US配列を切り替えても、押下時の物理キー情報に基づいて解放を試み、キー押しっぱなしの発生リスクを大幅に低減
* **安全停止設計**: 変換停止時やアプリ終了時に押下中の全キーの解放を試み、キー押しっぱなし（Stuck Keys）を防止（解放に失敗した未解放キーがある場合は警告を表示）
* **JIS / US 配列サポート**: Shift記号を含むキーバインドの確実な判別と送信（変換実行中の即時切り替えにも対応）
* **複数ポート監視**: 複数のMIDIポートからの同時受信が可能（同名デバイスや同一ノート番号もデバイス識別子により独立追跡）
* **オートフォーカス入力**: ノート番号・キー入力欄にフォーカスして実際のキーやMIDI鍵盤・ペダルを押すだけで自動設定（変換実行中も安全に利用可能）
* **柔軟な設定保存**: ワンクリック「上書き保存」と、用途別の「別名保存」・読込に対応
* **グローバルトグルホットキー**: 初期設定 `Ctrl + Alt + F9` でゲーム中や全画面状態でも変換の開始/停止を即座に切り替え可能（マッピングキーとの衝突自動防止機能つき、F12キーはシステム予約のため除外）
* **WinRTデバイス監視と独立プロセスWinMM内部診断**:
  * Windows 10/11 の WinRT API (`Windows.Devices.Midi`) によるOSレベルのデバイス認識と、独立プロセスWinMM（`--enum-winmm`）による最新ハードウェア接続状態の追従を内部診断として実装
  * 実機環境（KORG nanoKEY2等）でWinRTの列挙が0件となる場合でも、独立プロセスWinMMの結果を最重要視して誤切断を防止
  * 親プロセスのWinMMキャッシュに残存していても、新規プロセスWinMMで0件（消失）となった場合は確実に切断と判定して安全解放
  * ポート一覧には実際にMIDI入力として利用可能なポート名のみを表示
* **デバイス切断検知と安全停止**: Windowsのデバイス変更通知（`WM_DEVICECHANGE`）契機のヘルスチェックにより、演奏中のMIDI機器切断を検知した場合に押下中キーを解放して安全停止を試みます（※すべての環境で完全な動作を保証するものではありません）
* **診断ログ管理（debug_device.log）**:
  * 普段（通常起動時）はログファイルを出力しません。トラブルシューティング時のみ `--debug` または `--log` 引数を指定して起動することでログが出力されます
  * デバッグ出力時は起動ごとに上書きされ、前回のログは破棄されます（子プロセスの診断時には上書きされません）
  * デバッグ出力中も無制限に肥大化しないよう、約1MBのサイズ上限管理を実施
* **ポート開始の安全性とロールバック**: 一部ポートが失敗しても正常なポートのみで監視を継続し、全ポート失敗時は安全にロールバックしてエラー内容を明示
* **厳格なキー名検証**: 不明なキー名やマウス用仮想キーコード、不正な数値文字列を登録時およびJSON読込時に自動検証・拒否
* **キー送信エラーの通知集約**: SendInput失敗時にWin32エラーコードを即座に取得し、同一エラーの連続ダイアログを防ぎつつ通知
* **設定の自動復旧**: 既存JSON内の大文字表記（`PEDAL`）の自動正規化や、ホットキー衝突・予約キー（F12）設定時の安全な自動無効化

## 🔧 実行・開発環境

### ユーザー（実行のみ）の場合
配布された `midi2key.exe` と `settings.json` さえあれば、**ダブルクリックするだけで動きます（.NET等のインストール・環境構築は一切不要です）。**

### 開発・ビルドを行う場合
* **OS**: Windows 10/11 (64bit, Build 19041以上推奨)
* **SDK**: .NET 9.0 SDK
* 使用パッケージ (NuGet):
  * `InputSimulatorCore`
  * `Melanchall.DryWetMidi`
  * `MouseKeyHook`

## 🚀 使い方

1. アプリを起動すると、PCに接続されている利用可能なMIDIポートの一覧が表示されます。
2. 使用したいポートにチェックを入れます（複数選択可）。
   * **ポートが一覧に現れない・接続変更が反映されない場合**:
     MIDIデバイスの接続・切断後、ポート一覧が正常に更新されない場合があります。接続状態の変更を反映するには、midi2keyを終了して再起動してください。
3. 音程（ノート番号）と、割り当てたいキー（例: `a`, `1`, `enter`）をキー入力欄にセットします。
   * **MIDIノートの自動入力**: 「ノート/ペダル」入力欄にフォーカスした状態で電子ピアノの鍵盤を弾くと、自動的にノート番号が入力されます。
   * **ペダルの登録方法**: 「ノート/ペダル」入力欄に `pedal` と直接入力するか、入力欄にフォーカスした状態で接続したサステインペダルを1回踏み込むと自動で `pedal` と入力されます。変換したいキー（例: `space` や `shift`）を指定して `[追加]` を押してください。
4. `[追加]` ボタンでマッピングを登録します。
5. **`[変換開始]` ボタンを押すと変換がスタートし**、MIDIキーボードを弾くとPCキーボードのキーが入力されるようになります。
6. 設定を次回も使いたい場合は、**`[上書き保存]`** または **`[別名保存]`** を押して設定を保存してください。
   * **`[上書き保存]`**: 現在読み込んでいる設定ファイル（デフォルトは `settings.json`）にワンクリックで上書き保存します。
   * **`[別名保存]`**: ゲーム別・用途別の設定ファイルとして好きな名前・フォルダに保存します（保存成功後に自動で現在の読込ファイルとして適用されます）。
   * **`[設定読込]`**: 別途保存したJSON設定ファイルを読み込みます（演奏中に読み込んだ場合も、安全に全キーが解放・停止された上で新設定が適用されます）。

## 🛡 安定性と安全性についての仕様

* **変換停止時のキー自動解放と未解放キー警告**:
  * `[変換停止]` ボタンをクリックした際、およびアプリ終了時には、OS上で押下状態になっているすべてのキー（Shiftを含む）の物理解放を試みます。
  * OSやSendInputの状況によりキー解放に失敗した未解放キーが残っている場合は、ステータス欄に警告（「警告: 未解放キー N 件」）が表示され、未解放キーが解消されるまで次の変換開始が安全のため禁止されます。
* **演奏中のマッピング・配列変更**:
  * 鍵盤を押したまま画面上でマッピングを変更したり、JIS/US配列を切り替えたりした場合でも、NoteOn押下時点のキー情報（スナップショット）が保持されているため、指を離した際に押下時のキー解放を試みます。
* **ノート取得と変換の分離**:
  * ノート欄にフォーカスして新しいキー割り当てをキャプチャしている間も、すでに演奏中だったノートの解放処理は邪魔されず、キャプチャ用の打鍵がゲーム等に誤送信されることもありません。

## 💡 注意点 / 制限事項

* **ホットプラグ（USB抜き差し）に関する仕様と運用方針**:
  * **本アプリはホットプラグへの完全対応を保証するものではありません。**
  * Windowsの従来のMIDIサブシステム（WinMM `winmm.dll`）およびそれをラップするMIDIバックエンド（DryWetMIDI）には、**同一プロセス内で一度MIDIポートを列挙・初期化すると、実行中のPnP変更（機器の挿抜）が内部キャッシュにより反映されない**という環境依存の既知の問題が存在します。
  * **MIDIデバイスの接続・切断後、ポート一覧が正常に更新されない場合があります。接続状態の変更を反映するには、midi2keyを終了して再起動してください。**
  * 接続変更の内部検知および安全停止処理は試みますが、すべての環境で完全な動作を保証するものではありません。
  * 機器を再接続した際、安全のため自動での変換再開は行われません。再接続・アプリ再起動後はユーザー自身の手動操作（`[変換開始]` ボタンまたはトグルホットキー）で変換を開始してください。
* **診断ログ（debug_device.log）の取り扱い**:
  * 普段（通常起動時）はログファイルを出力しません。また、ディスク上に残っている過去の `debug_device.log` は通常起動時に自動的に削除されます。
  * 接続トラブル等の調査時に `--debug` または `--log` 引数を付与して起動した場合にのみ `debug_device.log` を出力します（起動ごとに上書き初期化）。
  * ログ出力中のログサイズは最大約1MBに制限されており、上限超過時は古いログが自動整理されます。
* **実機未検証項目について**:
  * 以下の項目については、FakeMidiListener等の疑似イベントおよび診断比較ロジックによる自動テスト（全105件）で正当性を検証していますが、**Windows実機（KORG nanoKEY2等）での完全な動作は未検証**となります。実機環境での動作調査時は `--debug` オプションで起動して診断ログ（`debug_device.log`）を確認してください。
    * 起動後のMIDI機器接続および取り外し
    * 変換実行中の物理USB抜去
    * ノート押下中・ペダル踏み込み中の物理USB抜去
    * 複数デバイス接続時の一部切断
    * 再接続後の手動再開
    * Steamクライアント起動中や一部の排他全画面ゲームでのホットキー動作
* **ホットキーの競合**:
  * グローバルホットキー（RegisterHotKey）は、Steamや他の常駐ソフトウェア・ゲーム独自のショートカットキーと競合する場合があります。競合する場合は設定画面よりキーの組み合わせを変更してください（F12キーはWindowsシステム予約のため使用できません）。
* キー入力はOSの特権レベルに近い操作でエミュレートされます。環境や一部のゲーム（強力なカーネルレベルのアンチチートを持つもの等）では動作が制限されるか、管理者権限での実行が必要な場合があります。
* 本アプリの利用は自己責任でお願いします。

## 🛠 .EXE への自力ビルド手順

自身でカスタマイズしたあとに、環境依存のない配付用の **単一の `.exe` ファイル** を作成したい場合は、以下のコマンドをターミナルで実行します。

```powershell
dotnet publish MidiToKeyApp.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

正常に終了すると、`bin\Release\net9.0-windows10.0.19041.0\win-x64\publish\` フォルダの中に `midi2key.exe` がたった一つだけ（Native DLL等もすべて埋め込まれた状態で）生成されます。
